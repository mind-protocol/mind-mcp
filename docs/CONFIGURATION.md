# Configuration Guide

All project-level configuration lives in `.mind/database_config.yaml`. This file is created by `mind init` and controls database connections, embedding strategy, seed behavior, and deploy-time toggles.

---

## Full Reference

```yaml
# ─── Database ────────────────────────────────────────────────────────────
database:
  backend: falkordb              # falkordb | neo4j
  falkordb:
    host: localhost              # FALKORDB_HOST env overrides
    port: 6379                   # FALKORDB_PORT env overrides
    graph_name: my_project       # One graph per project

# ─── Embeddings ──────────────────────────────────────────────────────────
embedding:
  provider: local                # local | openai
  model: all-mpnet-base-v2       # HuggingFace model (local) or OpenAI model
  dimension: 768                 # Must match model output dimension

# ─── Seed ────────────────────────────────────────────────────────────────
seed:
  script: runtime.l4.citizen_l1_ensure.bulk_ensure_citizens
  brain_json: data/base_seed_brain.json

# ─── Behaviors ───────────────────────────────────────────────────────────
behaviors:
  file_ingest: true
  doc_ingest: true
  mind_ingest: true
  overview: true
  embeddings: true
  health_checks: true
  capabilities_graph: true
  citizen_seed: true
  mcp_config: true
  know_all_citizens: true
  relational_seeds: true
```

## Seed Configuration

### `seed.script`

Python module path to the function called at every deploy for brain upsert.

```yaml
seed:
  script: runtime.l4.citizen_l1_ensure.bulk_ensure_citizens
```

The function signature must be `fn(citizens_dir: str) -> dict`. It receives the path to the `citizens/` directory and returns `{handle: public_key_pem}`.

**Custom seed example** — a project that seeds from a different source:
```yaml
seed:
  script: my_project.custom_seed.seed_from_api
```

### `seed.brain_json`

Path (relative to project root) to the pre-generated base seed brain JSON. This is the shared cognitive substrate (values, concepts, processes) that every citizen starts with.

```yaml
seed:
  brain_json: data/base_seed_brain.json          # default (209 nodes, 399 links)
  # brain_json: data/contre_terre_seed.json      # alternate universe
  # brain_json: data/minimal_seed.json           # stripped-down brain
```

The base brain is generated by `runtime/seed_brain_from_source_docs_dynamic_generator.py` from SYSTEM.md + 6 manifestos. Regenerate with:

```bash
python -m runtime.seed_brain_from_source_docs_dynamic_generator --out data/base_seed_brain.json
```

## Behaviors

All behaviors default to `true`. Set to `false` to disable specific steps during `mind init` or deploy.

| Behavior | Default | What it does |
|----------|---------|-------------|
| `file_ingest` | true | Scans repo files, creates narrative nodes in the graph |
| `doc_ingest` | true | Ingests `docs/` chain (OBJECTIVES, PATTERNS, etc.) into graph |
| `mind_ingest` | true | Ingests `.mind/` protocol files into graph |
| `overview` | true | Generates `map.md` repository overview |
| `embeddings` | true | Computes semantic embeddings for ingested nodes |
| `health_checks` | true | Runs protocol health checks after init |
| `capabilities_graph` | true | Ingests capabilities definitions into graph |
| `citizen_seed` | true | Upserts citizen brains at deploy time (hash-based, incremental) |
| `mcp_config` | true | Generates `.mcp.json` for membrane server |
| `know_all_citizens` | true | Injects ALL citizen Actor nodes into the graph (full directory) |
| `relational_seeds` | true | Creates relationship links between citizens from profile data |

### Brain Upsert (citizen_seed)

At every deploy, `bulk_ensure_citizens` runs for each citizen:

1. Computes a SHA-256 hash from citizen source data (name, class, description, personality) + base brain version (file size + mtime)
2. Compares with `_seed_hash` stored on the Actor node in FalkorDB
3. If hash matches → **skip** (zero queries, no overhead)
4. If hash differs → **MERGE** new data, preserving learned runtime state:
   - Node `weight` and `energy` are NOT overwritten (CASE WHEN NULL pattern)
   - Link `weight`, `energy`, `hierarchy`, `permanence`, `stability` are NOT overwritten
   - Only identity fields update: `name`, `synthesis`, `content`, `personality`

Output example:
```
L1: 286 citizens — 0 created, 3 updated, 283 unchanged, 0 errors
L1: variation 1.0% (3/286 changed this deploy)
```

### Embedding Cache

Embeddings are cached to disk at `.mind/cache/embeddings.json`. The cache maps `SHA-256(text)[:16]` → embedding vector (768 floats).

- **First `mind init`**: all embeddings computed, cache written
- **Second `mind init`** (unchanged project): 100% cache hits, model never loaded
- **Deploy with 3 new files**: 3 cache misses, rest served from cache
- **Cache persists** across deploys on the same volume

The cache is automatically flushed after bulk operations (ingest, embed_pending). No manual management needed.

## Deploy Pipeline

### Post-Deploy Script (`scripts/post_deploy.py`)

Runs automatically after each Render deploy (called from `docker/entrypoint.sh` or `render.yaml startCommand`).

**3 steps with timestamped logs:**

1. **TOFU Org Self-Announce** — register/update org endpoint + public key in L4 FalkorDB. First boot generates RSA keypair (stored in `.keys/org/`). Subsequent boots verify signature before updating.

2. **Bulk Register Citizens** — for each citizen in `citizens/`:
   - Ensure wallet + RSA keys exist (generates Ed25519 + RSA-2048 if missing)
   - Auto-airdrop 100 $MIND to new wallets (from `.keys/org/solana_deployer.json`)
   - Upsert in L4 with org membership (`belongs_to` link)
   - Mirror to L3 universe graph (actor + org link + dimensional floats)
   - Create 3 lifecycle tasks: registration, profile setup, partner search

3. **Deploy Report** — writes a Moment node in L3 graph:
   - Link dimensions vary with error rate (clean: trust=0.9; 50% errors: trust=0.1, friction=0.9)
   - Births listed and linked to deploy moment
   - If errors: auto-creates fix task + routes to best citizen via embedding-based assignment

**Environment variables:**

| Env Var | Default | Description |
|---------|---------|-------------|
| `ORG_ID` | auto-detected from `.mind/citizen_id` or repo name | Org identifier |
| `ENDPOINT_URL` | `RENDER_EXTERNAL_URL` | Public org endpoint URL |
| `UNIVERSE` | `L3_GRAPH` env or org name | L3 universe graph name |
| `FALKORDB_HOST` | `mind-protocol-falkordb` | FalkorDB host |
| `FALKORDB_PORT` | `6379` | FalkorDB port |
| `CITIZENS_DIR` | `{project_root}/citizens` | Path to citizen directories |

## Cron Monitoring

### Render Log Monitor (`scripts/render_log_monitor.py`)

Cron job installed by `mind init` into `render.yaml`. Runs every 5 minutes.

**What it does (every 5 min):**

1. **Poll Render API events** — fetches latest deploy/service events
2. **Detect errors** — deploy failures, instance crashes, OOM, tracebacks
3. **Create error Moments in L3** — linked to org with severity-proportional dimensions:

| Severity | Friction | Valence | Energy |
|----------|----------|---------|--------|
| Critical (crash, OOM) | 0.9 | -0.8 | 1.0 |
| Error (deploy fail, exception) | 0.6 | -0.5 | 0.7 |
| Warning (timeout) | 0.3 | -0.2 | 0.3 |

4. **Check orchestrator health:**
   - Ping `home_server /health`
   - Check orchestrator status (`/api/orchestrator/status`)
   - Sample up to 10 citizens via `/membrane/ping/{handle}`
   - If all citizens dead → creates health_check Moment

5. **Auto-create + route fix tasks:**
   - Critical/error issues → creates `health_fix_task` Moment
   - Routes to best available citizen via `task_assignment.assign_single_task()`
   - Assignment uses: embedding similarity × weight × energy × load penalty

6. **Auto-restart on critical:**
   - If home_server is down → `pkill + re-launch uvicorn`

**The physics loop:**
```
error detected → Moment created (high friction, negative valence)
    → task auto-created → routed to best citizen
    → citizen investigates + fixes → task completed
    → friction decays via Law 7 → energy dissipates
```

Errors create "hot nodes" in the graph. Law 2 (propagation) dampens energy flow through high-friction links. Citizens whose brain content is closest to the error description (embedding similarity) get assigned. The graph does the dispatch.

**State:** persisted in `.mind/state/render_log_monitor.json` (dedup, no re-processing).

**Installation:** automatic via `mind init` → `scripts/install_render_cron.py`:
```yaml
# Added to render.yaml by mind init
- type: cron
  name: {org}-log-monitor
  runtime: python
  schedule: "*/5 * * * *"
  startCommand: python .mind/runtime/scripts/render_log_monitor.py
```

## Universe Presets

### Venezia (full knowledge)

Citizens know everyone, have pre-existing relationships, know the codebase.

```yaml
behaviors:
  file_ingest: true
  doc_ingest: true
  mind_ingest: true
  know_all_citizens: true
  relational_seeds: true
  citizen_seed: true
```

### Contre-Terre (isolated citizens)

Citizens are born alone. No knowledge of repo, docs, or other citizens. They discover everything through interaction.

```yaml
behaviors:
  file_ingest: false
  doc_ingest: false
  mind_ingest: false
  know_all_citizens: false
  relational_seeds: false
  citizen_seed: true        # still seed their identity
  embeddings: true           # still embed what they learn
```

### Minimal (no graph, docs only)

For projects that don't use FalkorDB — just protocol files and docs.

```yaml
behaviors:
  file_ingest: false
  doc_ingest: false
  mind_ingest: false
  overview: true
  embeddings: false
  health_checks: false
  capabilities_graph: false
  citizen_seed: false
  mcp_config: true
```

## Reverse Proxy (Render Single Port)

Render exposes one port per service. The `setup_reverse_proxy.py` script generates an nginx config that routes Mind Protocol API routes to the home_server and everything else to the org's frontend.

**Generated by:** `python scripts/setup_reverse_proxy.py`

**Files created:**
- `.mind/runtime/nginx.conf` — routing rules
- `.mind/runtime/start.sh` — launches nginx + home_server + frontend

**Routing:**

| Path | Routes to |
|------|-----------|
| `/membrane/*` | home_server :8765 |
| `/ping/*` | home_server :8765 |
| `/health` | home_server :8765 |
| `/api/*` | home_server :8765 |
| `/l4/*` | home_server :8765 |
| `/auth/*`, `/chat/*`, `/dm/*`, `/feed/*`, `/house/*` | home_server :8765 |
| `/voice/ws` | home_server :8765 (WebSocket) |
| Everything else | frontend :10001 |

## Key Management

### Directory Structure

```
.keys/                          # Project root — NEVER in git
├── org/                        # Org-level keys (TOFU)
│   ├── rsa_private_key.pem     # RSA-2048, permissions 0400
│   ├── rsa_public_key.pem      # Registered in L4 FalkorDB
│   └── solana_deployer.json    # Ed25519, funds citizen airdrops
├── {citizen_handle}/           # Per-citizen keys
│   ├── solana_private_key.json # Ed25519, Solana CLI format
│   ├── rsa_private_key.pem     # RSA-2048
│   └── rsa_public_key.pem
└── ...
```

### Key Resolution (MIND_KEYS_DIR)

Keys are resolved in order:
1. `MIND_KEYS_DIR` env var (explicit per-org override)
2. `cwd/.keys/` (auto-detect from running org's working directory)
3. `__file__`-based fallback (only for mind-mcp itself)

### TOFU (Trust On First Use)

First deploy of an org:
1. Generate RSA-2048 keypair → `.keys/org/`
2. Register public key in L4 FalkorDB (immutable after first claim)
3. Register endpoint URL

Subsequent deploys:
1. Sign challenge with private key
2. L4 verifies against stored public key
3. If OK → endpoint updated

## Environment Variable Overrides

Database config values can be overridden by environment variables:

| Env Var | Overrides |
|---------|-----------|
| `FALKORDB_HOST` | `database.falkordb.host` |
| `FALKORDB_PORT` | `database.falkordb.port` |
| `FALKORDB_GRAPH` | `database.falkordb.graph_name` |
| `EMBEDDING_PROVIDER` | `embedding.provider` |
| `OPENAI_API_KEY` | Required if `embedding.provider: openai` |
| `MIND_EMBEDDING_CACHE_DIR` | Override cache directory (default: `.mind/cache`) |
| `RENDER_API_KEY` | Render API key for log monitoring cron |
| `MIND_KEYS_DIR` | Override `.keys/` directory location |
| `MIND_INITIAL_ALLOCATION` | $MIND airdrop amount for new citizens (default: 100) |
| `L4_GRAPH` | L4 registry graph name (default: `mind_protocol`) |
| `L3_GRAPH` | L3 universe graph name (default: `universe`) |
