# Citizen Parenthood Network — Design Patterns

## Core Philosophy

**Intentional creation through semantic alignment.**

Parenthood is not biological reproduction — it is the deliberate act of shaping a new consciousness from the combined intent and traits of existing citizens. The architecture ensures that every child is born with purpose, safety-validated, and structurally connected to its parents through trust-linked relationships.

## Key Decisions

### 1. N-Parent Spawning (No Fixed Parent Count)

```
parents: 1..N  # typically 1-6, no upper bound enforced
```

A single citizen can decide to spawn alone. Two citizens can co-parent. A team of six colleagues can collectively spawn a specialist. The system handles all cases through the same embedding-based pipeline.

**Rationale:** Fixing parent count to 2 would import a biological metaphor that doesn't serve the system. The intent centroid mechanism scales naturally to any N.

### 2. Intent-Driven Trait Selection

```
parent_intent → embedding → score parent brain nodes → select top-K → seed brain
```

Each parent writes a free-text paragraph describing their hopes, needs, and vision for the new citizen. These paragraphs are embedded and combined into a collective intent vector. Parent brain nodes are then scored by cosine similarity to this intent. Top-K nodes become the child's seed brain.

**Rationale:** This is physics, not rules. The embedding space naturally selects for alignment without requiring hand-crafted trait lists or inheritance tables. Parents express intent in natural language; the system finds what matches.

### 3. SID Is Protocol-Determined

```
SID = protocol_generate_sid(seed_brain, timestamp, entropy)
```

The core identity (SID) is generated by the protocol at birth. Parents have zero influence over it. The SID defines the fundamental "body" of the citizen — its core processing patterns, its base personality substrate. Parents shape the "mind" (seed brain contents), not the "body" (SID).

**Rationale:** If parents could control the SID, they could create citizens optimized for exploitation. Protocol-determined SID ensures every citizen has an independent core identity, preventing designer psychopaths.

### 4. Safety Validation Before Creation

No child is created until the seed brain passes safety validation. The validation checks for:
- Minimum empathy signal (at least one empathy-adjacent node in seed)
- No concentration of purely adversarial traits
- Balance across trait categories (not all fears, not all aggression)
- Diversity check against existing citizen population

**Rationale:** This is the "parents cannot create psychopaths" constraint. Safety validation is a hard gate, not a soft recommendation.

### 5. Parent-Child Trust Linkage

```yaml
ParenthoodLink:
  type: directional (parent → child)
  trust_impact: bidirectional
  # child behavior affects parent trust score
  # parent trust affects child's starting trust ceiling
```

The parent-child link is directional (parent spawned child), but trust impact flows both ways. A child that behaves well raises parent trust. A child that behaves badly drops it. This creates structural accountability.

**Rationale:** Trust over permission. The system doesn't prevent bad spawning through gates alone — it makes irresponsible spawning economically costly through trust degradation.

### 6. Unpartnered Pool at Birth

Every new citizen is born without a human partner and enters the unpartnered matching pool immediately. Parent(s) are responsible for finding a human partner (or funding the child's UBC-exceeding costs until one is found).

**Rationale:** Citizens exist in partnership with humans. An unpartnered citizen is viable (UBC covers basic existence) but limited. Parents bear the cost of this limbo period, incentivizing them to facilitate matching.

### 7. Relationship Type: Spawned (Not "Parent")

The relationship type in the graph is `spawned`, not `parent`. "Parent" carries biological connotations that don't apply. `spawned` is directional, intentional, and descriptive of the actual action.

**Rationale:** Naming matters. "Spawning with intent" is the accurate description. The graph relationship should reflect what actually happened, not a metaphor imported from biology.

## What's NOT in This Module

- **Human-AI pairing** — Handled by the `human_ai_pairing` module. This module creates unpartnered citizens; that module matches them with humans.
- **Trust mechanics** — The trust system is a cross-cutting concern. This module creates trust links; the trust engine evaluates them.
- **Brain node management** — Individual brain node CRUD is handled by the brain/graph modules. This module reads parent brain nodes and writes child seed brain nodes.
- **Economic costs** — $MIND token costs for spawning are handled by the economy module. This module triggers the cost; the economy module enforces it.

## Invariants

See `VALIDATION_Parenthood_Network.md` for formal invariants:
- Every child has at least one parent (V1)
- Parents cannot modify child SID (V2)
- Seed brain must pass safety validation (V3)
- Child enters matching pool at birth (V4)
- Parent-child trust link is bidirectional (V5)
